Node.js + Express Revision

Format for every concept below:
-- Short Note
🧠 Mnemonic
Example
📌 Real-time Scenario



*** What is Node.js ***
-- Node.js is a runtime environment that lets JavaScript run OUTSIDE the browser (on the server), built on Chrome's V8 engine
-- Single-threaded, event-driven, non-blocking I/O → handles many requests without creating a new thread for each

🧠 Mnemonic: "Node = JS escapes the browser, runs on the server"

Example:-
console.log("Hello from Node.js"); // run with: node app.js

📌 Real-time Scenario: Building the backend/API server for a web app (like the server behind Instagram's feed, login, etc.) using the same JS language used on the frontend.



*** Node.js Architecture (Event Loop + Non-blocking I/O) ***
-- Single thread runs your JS code, but heavy/slow tasks (file read, DB query, network call) are offloaded to libuv (background), and their callback runs later via the Event Loop
-- This is why Node doesn't "wait" for slow tasks → stays fast for many concurrent users

🧠 Mnemonic: "One thread, but never waits — throws slow work to the background, moves on"

Example:-
console.log("1");
setTimeout(() => console.log("2"), 0);  // offloaded, runs later
console.log("3");
// Output: 1, 3, 2

📌 Real-time Scenario: A single Node server handling thousands of users uploading files simultaneously without freezing, because file writes don't block other users' requests.



*** Modules (CommonJS: require / module.exports) ***
-- Every file in Node is its own module, use module.exports to expose code, require() to import it

🧠 Mnemonic: "export OUT with module.exports, bring IN with require"

Example:-
// math.js
function add(a, b) { return a + b; }
module.exports = { add };

// app.js
const { add } = require('./math');
console.log(add(2, 3)); // 5

📌 Real-time Scenario: Splitting a large app into separate files — routes.js, db.js, utils.js — and importing only what's needed in each file, keeping code organized.



*** npm & package.json ***
-- npm = Node Package Manager, used to install/manage libraries (packages)
-- package.json → holds project info, dependencies, and scripts

🧠 Mnemonic: "package.json = the project's ID card + shopping list of dependencies"

Example:-
npm init -y                 // creates package.json
npm install express         // installs express, adds to "dependencies"
npm install -D nodemon       // installs as dev dependency

// package.json
"scripts": {
    "start": "node app.js",
    "dev": "nodemon app.js"
}
// run with: npm run dev

📌 Real-time Scenario: Onboarding a new developer to a project — they just run `npm install` and package.json installs the EXACT same dependencies everyone else on the team is using.



*** fs module (File System) ***
-- Built-in module to read/write files, has both sync (blocking) and async (non-blocking) versions

🧠 Mnemonic: "fs.readFile = don't wait (async) | fs.readFileSync = wait here (blocks everything)"

Example:-
const fs = require('fs');

// Async (preferred)
fs.readFile('data.txt', 'utf8', (err, data) => {
    if (err) throw err;
    console.log(data);
});

// Sync (blocks the whole thread until done)
const data = fs.readFileSync('data.txt', 'utf8');

📌 Real-time Scenario: Reading a large log file or config file at server startup — using async so the server doesn't freeze for other incoming requests while reading.



*** http module (Node's built-in server, before Express) ***
-- Node can create a web server WITHOUT any framework using the built-in http module

🧠 Mnemonic: "http.createServer((req,res)=>{}) = raw server, no shortcuts"

Example:-
const http = require('http');

const server = http.createServer((req, res) => {
    res.writeHead(200, { 'Content-Type': 'text/plain' });
    res.end('Hello World');
});

server.listen(3000, () => console.log('Server running on port 3000'));

📌 Real-time Scenario: Understanding what Express does under the hood — this raw version shows why frameworks like Express exist (this gets messy fast for real routing/middleware needs).



*** What is Express & why use it ***
-- Express is a minimal web framework built ON TOP of Node's http module
-- Makes routing, middleware, request/response handling MUCH simpler than raw Node

🧠 Mnemonic: "Express = Node's http module, but easy and organized"

Example:-
const express = require('express');
const app = express();

app.get('/', (req, res) => {
    res.send('Hello Express');
});

app.listen(3000, () => console.log('Server running on port 3000'));

📌 Real-time Scenario: Building a REST API for a food delivery app (menu, orders, users) — Express handles routing for /menu, /orders, /users cleanly instead of manually checking req.url like raw Node.



*** Routes (GET, POST, PUT, DELETE) ***
-- Each route = a URL path + HTTP method + handler function (this is the core of REST APIs)

🧠 Mnemonic: "GET-read, POST-create, PUT-update, DELETE-remove"

Example:-
app.get('/users', (req, res) => res.send('Get all users'));
app.post('/users', (req, res) => res.send('Create a user'));
app.put('/users/:id', (req, res) => res.send('Update a user'));
app.delete('/users/:id', (req, res) => res.send('Delete a user'));

📌 Real-time Scenario: A Todo app's backend — GET /todos (list tasks), POST /todos (add task), PUT /todos/:id (mark complete), DELETE /todos/:id (remove task).



*** Route Params & Query Params ***
-- Route param (:id)  → part of the URL PATH, used to identify a specific resource
-- Query param (?key=value) → optional extra data after "?", used for filtering/searching/pagination

🧠 Mnemonic: "Params = WHICH one (path), Query = HOW/filter (after ?)"

Example:-
// URL: /users/5?sort=asc
app.get('/users/:id', (req, res) => {
    console.log(req.params.id); // "5"
    console.log(req.query.sort); // "asc"
    res.send(`User ${req.params.id}, sorted ${req.query.sort}`);
});

📌 Real-time Scenario: An e-commerce product page /products/101?color=red&size=M — 101 (route param) picks the exact product, color/size (query params) are optional filters.



*** Middleware ***
-- A function that runs BETWEEN the request and the final response, has access to (req, res, next)
-- Must call next() to pass control to the next middleware/route, otherwise request hangs

🧠 Mnemonic: "Middleware = checkpoint in the middle, must call next() to let request pass"

Example:-
function logger(req, res, next) {
    console.log(`${req.method} ${req.url}`);
    next();   // ✅ without this, request gets stuck here forever
}

app.use(logger);   // runs for EVERY request

app.get('/', (req, res) => res.send('Home'));

📌 Real-time Scenario: Logging every incoming request, checking authentication tokens, or validating request data — all BEFORE the actual route logic runs.



*** express.json() (Body Parsing Middleware) ***
-- Built-in middleware that parses incoming JSON request body and makes it available as req.body
-- Without it, req.body is undefined for JSON requests

🧠 Mnemonic: "express.json() = unlocks req.body from raw JSON"

Example:-
app.use(express.json());   // must add this BEFORE routes that need req.body

app.post('/users', (req, res) => {
    console.log(req.body);  // { name: "Vaibhav", age: 25 }
    res.send('User received');
});

📌 Real-time Scenario: A signup form on the frontend sends { name, email, password } as JSON — express.json() lets the backend actually read that data from req.body.



*** Express Router (Modular Routes) ***
-- Splits routes into separate files instead of putting everything in one big app.js, keeps code organized

🧠 Mnemonic: "Router = mini Express app for ONE feature, plugged into the main app"

Example:-
// routes/users.js
const express = require('express');
const router = express.Router();

router.get('/', (req, res) => res.send('All users'));
router.get('/:id', (req, res) => res.send('One user'));

module.exports = router;

// app.js
const userRoutes = require('./routes/users');
app.use('/users', userRoutes);   // final path: /users, /users/:id

📌 Real-time Scenario: A large app with separate route files — userRoutes.js, productRoutes.js, orderRoutes.js — each handling its own feature instead of one massive 1000-line app.js.



*** Serving Static Files ***
-- express.static() serves files (images, CSS, HTML, JS) directly from a folder without writing a route for each one

🧠 Mnemonic: "express.static('public') = whole folder becomes directly accessible"

Example:-
app.use(express.static('public'));
// public/logo.png is now accessible at: http://localhost:3000/logo.png

📌 Real-time Scenario: Serving a website's images, CSS, and client-side JS files, or serving a built React app's production files from Express.



*** Error Handling Middleware ***
-- Special middleware with 4 params (err, req, res, next), placed at the END of all routes, catches errors from anywhere in the app

🧠 Mnemonic: "4 params (err first) = error handler, always goes LAST"

Example:-
app.get('/crash', (req, res) => {
    throw new Error('Something broke!');
});

// Error handling middleware (must be defined AFTER all routes)
app.use((err, req, res, next) => {
    console.error(err.message);
    res.status(500).send('Something went wrong!');
});

📌 Real-time Scenario: If a database query fails unexpectedly anywhere in the app, this catches it centrally and sends a clean "500 Internal Server Error" response instead of crashing the whole server.



*** Full REST API / CRUD Example ***
-- Putting routes + middleware + params together into a working mini API

🧠 Mnemonic: "CRUD = Create, Read, Update, Delete → POST, GET, PUT, DELETE"

Example:-
const express = require('express');
const app = express();
app.use(express.json());

let todos = [{ id: 1, task: "Learn Express" }];

app.get('/todos', (req, res) => res.json(todos));                     // Read all
app.post('/todos', (req, res) => {                                     // Create
    const todo = { id: Date.now(), task: req.body.task };
    todos.push(todo);
    res.status(201).json(todo);
});
app.put('/todos/:id', (req, res) => {                                   // Update
    const todo = todos.find(t => t.id == req.params.id);
    todo.task = req.body.task;
    res.json(todo);
});
app.delete('/todos/:id', (req, res) => {                                // Delete
    todos = todos.filter(t => t.id != req.params.id);
    res.status(204).send();
});

app.listen(3000);

📌 Real-time Scenario: This exact pattern is the backend for almost any CRUD app — Todo lists, blog posts, product catalogs, comments sections.



*** Connecting Express to MongoDB (Mongoose) ***
-- Mongoose is an ODM (Object Data Modeling) library that makes it easy to connect Node/Express to MongoDB using Schemas & Models

🧠 Mnemonic: "Mongoose = Schema defines shape, Model does the DB talking"

Example:-
const mongoose = require('mongoose');
mongoose.connect('mongodb://localhost:27017/myapp');

const userSchema = new mongoose.Schema({
    name: String,
    email: String
});
const User = mongoose.model('User', userSchema);

app.post('/users', async (req, res) => {
    const user = await User.create(req.body);   // saves to MongoDB
    res.status(201).json(user);
});

📌 Real-time Scenario: Storing actual user signup data, blog posts, or orders permanently in a database instead of an in-memory array that resets every time the server restarts.



*** Environment Variables (dotenv) ***
-- Keeps sensitive/config values (DB URL, API keys, PORT) OUT of the code, stored in a .env file instead

🧠 Mnemonic: "dotenv = secrets live in .env, NEVER hardcoded, NEVER committed to git"

Example:-
// .env
PORT=3000
DB_URL=mongodb://localhost:27017/myapp

// app.js
require('dotenv').config();
const port = process.env.PORT;
console.log(port); // 3000

📌 Real-time Scenario: Using different database URLs/API keys for local development vs production deployment, without ever hardcoding secret keys directly in the source code (and .env is added to .gitignore).



*** CORS (Cross-Origin Resource Sharing) ***
-- By default, browsers BLOCK requests from a frontend on one origin (e.g. localhost:3000) to a backend on a different origin (e.g. localhost:5000)
-- cors middleware allows the backend to explicitly permit those cross-origin requests

🧠 Mnemonic: "CORS = backend's permission slip letting other origins talk to it"

Example:-
const cors = require('cors');
app.use(cors());   // allows all origins (use options to restrict in production)

📌 Real-time Scenario: React app running on localhost:3000 calling an Express API on localhost:5000 — without cors(), the browser blocks the API response with a CORS error.



*** JWT Authentication (basics) ***
-- JSON Web Token → after login, server generates a signed token containing user info, client sends it back on future requests (usually in Authorization header) to prove identity, without needing sessions/cookies

🧠 Mnemonic: "JWT = a signed ID card, server trusts it without re-checking password every time"

Example:-
const jwt = require('jsonwebtoken');

// on login
const token = jwt.sign({ userId: user.id }, 'secretKey', { expiresIn: '1h' });
res.json({ token });

// protecting a route
function auth(req, res, next) {
    const token = req.headers.authorization?.split(' ')[1];
    try {
        req.user = jwt.verify(token, 'secretKey');
        next();
    } catch {
        res.status(401).send('Invalid token');
    }
}

app.get('/profile', auth, (req, res) => res.send(req.user));

📌 Real-time Scenario: After logging into an app, the frontend stores the JWT and sends it with every API request (like viewing "My Orders") so the backend knows who's asking without requiring login again.



*** async/await Error Handling in Routes ***
-- Route handlers doing DB calls are usually async — errors inside await calls must be caught, otherwise the app can crash or hang

🧠 Mnemonic: "async route = wrap in try/catch, or it silently breaks"

Example:-
app.get('/users/:id', async (req, res) => {
    try {
        const user = await User.findById(req.params.id);
        if (!user) return res.status(404).send('User not found');
        res.json(user);
    } catch (err) {
        res.status(500).send('Server error');
    }
});

📌 Real-time Scenario: Fetching a user profile by ID from the database — if the DB is down or the ID is invalid, try/catch ensures the app sends a proper error response instead of crashing the whole server.
